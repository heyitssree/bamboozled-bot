### Added: `bamboozled/engine/`
| File | Contents |
|---|---|
| `api.py` | `Engine` protocol, `GameConfig`, `Intent`, `Event`, `Result`, `ResultRow`, `Question`, `IllegalIntent` (codes: not_in_game, not_your_turn, bad_phase, bad_index, bad_target, bad_rule, bad_choice, too_late, already_answered, over) |
| `bamboozled.py` | The turn engine. A turn is an agenda of steps walked until the game needs a question or a player decision, so cards, the wheel and the monkey nest without recursion and survive a restart as plain data |
| `fff.py`, `survival.py` | The other two modes |
| `rules.py`, `cards.py`, `wheel.py`, `scoring.py` | Constants and the eleven laws, the decks, the wheel, ranking and the personal-best rule |
| `bots.py` | Legal-move listing and a play-to-the-end driver (property tests, CLI, later the load test) |

Design points: `apply` returns a new state and never touches the one it was given; all randomness comes from a
`random.Random` state carried inside the game state (same seed, same game); time is `now_ms`; questions are supplied
from outside (`needs_question` / `supply_question`), so the engine does no I/O; `view_for` is the only way state
leaves and never contains the correct index before the reveal, other players' pending FFF answers, or Mist-hidden
scores. Every decision the old UI asked for is an intent with a legal-move check.

### Bugs found by writing the engine tests (fixed)
- A leaving player's follow-up decisions (a card that leads to a spin or a target pick) left the room waiting on them
  until the deadline; the main loop now auto-resolves anything pending on a leaver.
- FFF: a player who locked an answer and then left lost the points for that answer; the locked answer now counts and
  they are removed when the round ends.

2. Final rankings break ties by user id (the order the database uses); turn and spin order inside a game still follow

3. Intent idempotency on a client message id is a server concern (Phase 3), not the engine's.

  token is configured). SIGTERM sends `BYE{server_restart}`, then exits.
- `bamboozled/server/`: `auth.py` (Discord `users/@me` plus the activity-instance lookup with the bot token; retries 3 x

  never stored), `proxy_sig.py` (Ed25519 via PyNaCl, off by default), `results.py` (one transaction per game).

### Bugs found by the integration tests (fixed)
- The first `STATE` was queued before the socket's writer task existed and was never sent; the writer is now woken on
  start-up. (Unit tests on the manager alone could not have caught this.)
- A leaving player's follow-up decisions (Phase 2 fix) and an origin-verify rejection that never answered the
  WebSocket handshake.
- Housekeeping: `.coverage` had been committed in Phase 2; untracked and ignored.

### Deviations to note
1. **Tickers and tasks.** The spec describes one asyncio task per room. Rooms are synchronous state machines advanced
   by one server ticker (`pump`, every 0.25 s), which makes them fully testable with a fake clock and serialises all
   intents trivially.
2. **Disconnected players.** After the grace period the player is removed through the engine's `LEAVE` (their seat is
   dropped; on return they are a spectator) instead of being "timed out" turn by turn, so a dead connection can never
   hold a room up.
3. Hit-by-hit load numbers measure the server's own work in-process (no network), as the in-process method keeps the run
   repeatable; the same tool is to be run again on the VM in Phase 8.
4. `auth.authenticate` raises `AuthError` with a close code instead of returning `None`, so clients get a specific
   reason (4401 / 4403 / 4404).
5. Privacy endpoints (`/api/privacy/*`) and the live opted-out set are Phase 5; the AUTH hook that refuses opted-out
   users is in place and tested.

- Discord's real response shapes for the activity-instance lookup and whether the signed proxy headers reach REST
  calls or the WebSocket upgrade: both are marked in the code and are Phase 7 checks (spec 8.1, 12.2).
- A run against the real Discord API (needs owner input #1, the separate test application).

## Phase 5 - Bot surface, settings, privacy

Status: **built, awaiting owner sign-off.** Branch `v2/phase-5-bot` (from `main`, which holds the approved Phases 0 to 4).
Custom questions (`/teach`, spec 10.5) are not built, as decided in the owner decisions log.

### Built
- **Commands** (spec 10.1): the App Launcher **Launch** entry point keeps Discord's default handler; `/play` launches the
  Activity (`launch_activity`, with a plain "open the App Launcher" fallback if Discord refuses); `/stats [user] [mode]`;
  `/leaderboard [mode] [scope]` (`/quizstats` is a thin alias of it for one release); `/privacy status|opt_out|opt_in`;
  `/help` with a screenshot; `/bamboozled-admin ...`. The legacy `/bamboozled`, `/fff`, `/survival` load only while
  `feature.text_mode` is on and are added or removed at run time when it is switched, with a re-sync. The old
  `/bamboozled-activity` launcher (it called the retired Activity backend) is deleted.
- **Settings registry** (`bamboozled/settings/registry.py`, spec 10.2): one declaration per setting (kind, bounds, choices,
  default, legacy keys). Panel, `set`, import and export all read it; the game server reads values at use time so a change
  applies to the next room at once; values live in the `settings` table with who changed them; an unknown key or invalid
  stored value stops start-up. One setting added: `game.reveal_pause_seconds` (see "Found").
- **Admin** (`/bamboozled-admin`, owner or `system.panel_role`, hidden from non-administrators by default): `panel` (pick a
  category, see each setting with a marker where it differs from the default, then toggle, edit in a modal, reset or go
  back), `set`/`get`/`reset` with autocomplete and validation, `status` (uptime, rooms and sockets, games by mode, last
  Discord instance-lookup and token-check results, database size), `rooms` (list live rooms; close one; message its
  players, shown as a toast in the Activity), `export`/`import` (all-or-nothing), `testing on|off` (replaces the old
  test-mode command: games in a testing server are not recorded and post no card).
- **Privacy** (`/privacy`, `/api/privacy/*`, spec 10.3): opting out explains what is deleted, needs a Confirm within 60
  seconds, refuses during a running game (setting), writes `privacy.db` first, then the in-memory set, then one transaction
  deleting the user's `match_results` and `stats` and any match left empty, then forgets their cached name. Opting in waits

### Found and fixed while building
- **The answer reveal lasted one server tick.** After a Fastest Fingers round (and after a Survival answer, or a Bamboozled turn that
  ends) the next question replaced the result within 0.25 s, so players barely saw who won. The old game paused 3 s. The
  server now holds each result for `game.reveal_pause_seconds` (default 3, settable 0 to 10) without taking time from the
  next question. This also explained intermittent end-to-end failures that waited for the result screen.
- Loading and unloading the old cog in the new tests removed it from `sys.modules`, so old characterisation tests
  re-imported an unpatched copy; they now use the module their harness patched.
- A nested f-string that is only valid on Python 3.12 (the project targets 3.11) was caught and rewritten.
- The registry's bounds rejected two test-only values (grace 3 s, 200 rooms): the tests now use legal ones.

### Deviations and honest limits
1. **Not run live:** no real Discord application is available here (owner input #1), so the spec's "manual run with two accounts"
   was not done. Everything above uses the real cogs, views, services and database with fake interactions. Unverified against
   real Discord: `launch_activity` behaviour from slash commands and buttons, slash-command sync, the persistent button after
   a real restart, modals and the select-menu panel as rendered.
2. The legacy text games stay in their old files (not moved to `legacy_text/`); they are deleted one release after cutover.
3. `/bamboozled-admin status` shows "not active yet" for safety rejections (Phase 6) and "not configured" for backups
   (Phase 8). Trivia health shows the offline source.
4. The old per-guild `/bamboozled testmode` still uses its own table; the new `testing on|off` uses the settings registry.
5. `/privacy` is the only way back for an opted-out user: they cannot open the Activity (AUTH is refused, with that message).

## Phase 6 - Trivia screening (branch `v2/phase-6-trivia`)

### What was built
- `bamboozled/services/safety.py`: whole-word screening (NFKC fold, zero-width strip, leet map, stretched letters, tokens
  that keep Malayalam vowel signs). Tiers: `always`, `contextual` (only when `trivia.safety_strictness` is `strict`), and
  the owner's `blocklist.txt`. Spaced-out evasion: long entries match squashed text; short ones match a run of 1-2
  letter tokens ("f u c k", "fu-ck") that joins up to the entry exactly. `allowlist.txt` exempts single words.
- `data/safety/`: `always.txt` and `contextual.txt` are the v1 word list split into tiers, copied by script from the
  baseline commit (nothing added, none typed by hand). `blocklist.txt` and `allowlist.txt` are empty with a format header.
- `services/trivia_source.py`: `ScreenedQuestions` is now the provider for every mode. Sources per `trivia.sources`
  (OpenTDB, The Trivia API, both, or `custom_only`); question, category and every answer are screened; a rejection
  fetches another (max 5); a failing source is left alone for 30 s; the whole live attempt has an 8 s budget; anything
  else falls back to `custom_questions.json`. The same question is not asked twice in a row of 500.
- `/bamboozled-admin status`: per-source health, questions served per source, rejections since start (per source and
  category are counted; the panel shows per source).
